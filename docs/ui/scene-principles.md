# Scene Principles — 設計原則・追加基準

## シーン追加の判断基準

新しいシーンを追加する前に以下を確認する。

```
□ このシーンは独立して再利用できるか？ → Yes → scenes/ui/ または scenes/game/
□ 既存シーンに追加するだけで済むか？ → Yes → 新規シーンは作らない
□ 100行を超えそうか？ → Yes → サブシーンに分割を検討
□ 複数のゲームロジックを持とうとしていないか？ → Yes → Autoload に移す
```

## Claude Code 実装停止チェックリスト

以下のいずれかに該当する場合、**実装を停止してユーザーに確認する**。

```
□ シーンスクリプトが 100行を超えようとしている
□ シーンが SaveManager や GameManager を直接呼ばずに状態を変更しようとしている
□ ゲームロジック（スコア計算・当たり判定の判定式）をシーンに書こうとしている
□ get_node("../../xxx") のハードコードパスを使おうとしている
□ 1シーンで3つ以上の責務を持とうとしている
```

## 良いシーン設計の条件

- ✅ 1シーン = 1責務（メインメニュー、プレイヤー、コイン等）
- ✅ シグナルで親・兄弟シーンと通信する
- ✅ @export でシーンをテスト可能・設定変更可能にする
- ✅ Autoload への直接参照はなるべくシグナル経由にする
- ✅ UIシーンはゲームロジックを知らない

## 避けること

- ❌ 神シーン（ゲームワールドに全ロジックを詰め込む）
- ❌ シーンを `get_node()` で名前検索する
- ❌ _process() で状態を直接 GameManager に書き込む
- ❌ シーン同士が直接参照し合う（兄弟シーン間）
